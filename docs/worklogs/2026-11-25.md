### 수행과 관찰

- TASKS: 작업 목록·본문에 DOC-013을 등록하고, 관리 원칙의 Issue 링크를 개인 저장소로 바꿨다(과거 링크는 팀 저장소를 가리키는 기록으로 유지). 상태 "완료" 정의의 리뷰를 1인 개발에서는 자기 검토로 읽도록 연결했다.

- gitleaks: 변경 전 `gitleaks git --redact .`(176개 커밋)과 `gitleaks dir --redact .`가 각각 1건을 보고했다. 위치는 `tests/integration/online.db.test.ts:87`의 `createAppServer`에 넘기는 통합 테스트 전용 `sessionSecret` 리터럴(규칙 `generic-api-key`)로, 운영 값이 아님을 확인했다. 두 검사의 지문(이력: 커밋 `4d44bc3` 포함, 작업 폴더: 경로만)을 `.gitleaksignore`에 근거 주석과 함께 등록한 뒤 두 검사 모두 "no leaks found"로 끝났다.

문서 정합성 검사(사용자 후속 요청 "문서 정합성 검사하고 개인프로젝트 시작 pr 올리자"):

- 협업 규칙 문구: AGENTS·README·CONTRIBUTING·PRD·DESIGN·design/·templates에서 "두 개발자·상대방·교차 리뷰·담당 조율·리뷰 후" 등을 찾았다. 현행 규칙 문서에 1인 개발과 충돌하는 문구는 없었다. PRD·설계의 "두 사람"은 경기 참가자를 뜻한다. TASKS·DECISIONS·PROGRESS의 두 개발자 표현은 전환 전 기록이라 유지했다. 남은 수용 기준의 "리뷰 후 병합"은 TASKS 완료 정의에 따라 자기 검토로 읽는다.

수용 기준 판정: 병합 기준을 제외한 5개 충족.

### 한계·미검증

- `.gitleaksignore` 지문은 줄 번호를 포함하므로 해당 테스트 파일의 줄이 옮겨지면 작업 폴더 지문을 다시 등록해야 한다. 이력 지문은 커밋에 묶여 있어 유지된다.
- 저장소에 gitleaks를 실행하는 Git 훅·CI는 없어 로컬 수동 실행으로만 확인했다.
- 문서 형식은 의존성이 설치되지 않은 환경이라 `npx prettier`(3.10.1, 저장소 지정 3.9.10과 다름)로 변경 파일만 `--check`해 통과했고, 변경한 상대 링크·앵커가 실제 파일·제목과 맞는지 스크립트로 확인했다.
- 코드는 바꾸지 않아 `npm test`·`npm run build`는 실행하지 않았다.

### 문서 대조·후속 작업

- 운영 서비스 재개 여부와 운영 계정(Render·Neon·UptimeRobot)은 미정이다. 정하면 [OPERATIONS](../design/OPERATIONS.md)·README 배포 절과 새 결정을 함께 갱신한다.

### 수행과 관찰

- 분리: TASKS를 `## ` 절 단위(코드 블록 안 제목 제외)로 나눠, 관리 원칙·새 작업 등록 양식·DOC-013은 새 TASKS에, 나머지(상태·우선순위 스냅숏, 작업 목록 표, 작업 64건 절)는 `docs/legacy/TASKS-team.md`에 넣었다. 진행 중이던 12건은 표와 본문의 `상태:`를 "진행 중 → 종료(DEC-092)"로 바꿨다. 옛 PROGRESS는 머리말만 바꿔 `docs/legacy/PROGRESS-team.md`로 옮기고 새 PROGRESS를 다시 썼다.

- 링크 변경 규칙: 대상 앵커가 새 TASKS에 있으면 그대로 두고, legacy에만 있으면 legacy로 바꿨다. 과거 기록(2026-11-25 이전 worklog, legacy 파일, DECISIONS의 DEC-001~090 행)은 TASKS·PROGRESS 링크를 legacy로 보냈다(앵커 없는 링크 포함). 옮긴 legacy 파일의 상대 경로는 `docs/legacy/` 기준으로 다시 계산했다. 바뀐 링크가 있는 파일은 DECISIONS·CHANGELOG·CREDITS·PRD·DESIGN·ENGINEERING-VALIDATION·ADR 3개·design/ 7개·worklog 10개다.
- 내용 보존 확인(스크립트):
  - legacy가 아닌 수정 파일 25개는 TASKS·PROGRESS 링크 경로를 같게 놓고 비교했을 때 원본과 같다. 링크 외 변경 0건.
  - 첫 실행에서 링크 정규화가 관련 없는 디렉터리 링크의 끝 `/`를 지운 것(worklog 2026-11-04·11-05의 `artifacts/…/` 6곳)을 이 비교로 찾았다. TASKS·PROGRESS가 아닌 링크는 건드리지 않게 고쳐 처음부터 다시 실행했다.
  - legacy TASKS·PROGRESS는 상대 링크를 절대 경로로 풀어 원본과 줄 단위로 대조했다. 원본에 있고 legacy에 없는 줄은 새 TASKS로 옮긴 절(관리 원칙·등록 양식·DOC-013), 종료로 바꾼 12건의 상태 줄·표 행, 옛 PROGRESS 제목뿐이었다.
