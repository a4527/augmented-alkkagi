## DOC-016 운영 보완 결정과 작업 등록

### 범위와 기준 문서

- 작업: [DOC-016](../TASKS.md#doc-016-운영-보완-결정과-작업-등록)
- 결정: [DEC-094](../DECISIONS.md#결정-색인)
- 이번 작업 범위와 비교할 기준: 사용자가 클라우드 엔지니어·DevOps·솔루션 아키텍트 관점의 보완점(보안·운영·모니터링·CI/CD·검증·테스트) 정리를 요청했다. 정리 결과에서 Claude가 결정을 요청한 4개 항목에 사용자가 답했다: "배포 자동화, 월 비용 0원 유지, render를 써도 되고 다른걸 고려해도되는데 0원이 목표야. 백업은 일단 보류". 코드·배포 설정은 바꾸지 않는다.

### 작업·검증 조건

- 브랜치: `docs/doc-016-ops-hardening-plan`(기준 `main` `f8ffa64`)
- 환경: WSL2 Linux, Python 3 스크립트(문서 수정·링크 검사), gitleaks 8.30.1

### 수행과 관찰

보완 검토 때 확인한 현재 상태(정리의 근거):

- CI: `.github/` 디렉터리가 없어 PR·푸시 검사가 없다. `gh api .../branches/main/protection`이 "Branch not protected"(404)를 돌려줬다. 저장소는 공개다. 로컬 Git 훅(`core.hooksPath`·`.git/hooks`)도 설치돼 있지 않다.
- 배포: `render.yaml`은 `autoDeployTrigger: 'off'`, 무료 플랜, 싱가포르, `healthCheckPath: /health`다.
- 보안:
  - 이미 있는 것: 세션 쿠키 httpOnly·sameSite=lax·운영 secure, 로그인 시 세션 재발급(`auth/sessions.ts`), `/api/auth` IP당 분당 20회, `room:join` 사용자당 분당 30회, REST 본문 10KB, `x-powered-by` 끔.
  - 없는 것: 보안 헤더(CSP 등). Socket.IO는 `new Server(httpServer)` 기본 설정이라 출처 확인이 없고 메시지 크기 상한이 기본값이다. 경기 명령·스트림(`game/game-handlers.ts`)에는 빈도 제한이 없다.
  - 사용자당 소켓은 새 연결이 기존 연결을 대체한다(`realtime/connections.ts`).
- 의존성: `npm audit --omit=dev`가 "found 0 vulnerabilities"였다.

반영한 변경:

- DECISIONS: DEC-094(① 배포 자동화, CI 통과 전 배포 금지, 배포 뒤 확인·알림 ② 월 0원 유지 ③ 호스팅 재검토 허용, 정하기 전까지 Render 유지 ④ 외부 백업 보류)를 추가했다. DEC-013(배포 서비스 재검토 중)·DEC-029(수동 배포 대체)·DEC-047(수동 배포 대체 표시)의 대체 관계에 연결했다. CI 통과 전 배포 금지·배포 뒤 확인·작업 분할은 Claude가 정했다고 동의 근거에 밝혔다.
- OPERATIONS:
  - 상태 표에 자동 배포를 승인된 미구현 설계로 추가하고 호스팅 재검토를 미정으로 추가했다.
  - 배포·롤백 절 머리에 "구현 전까지 수동 배포 유지"를 적었다.
  - 백업 절에 외부 백업 보류를, 미정 목록에 호스팅·운영 재개·자동 배포 방식·모니터링 서비스를 각 작업에 연결해 추가했다.
- TECH_STACK: 배포 행에 0원 조건의 호스팅 비교 중임을 적었다.
- TASKS: DOC-016과 보완 작업 6건(CI-001·SEC-001·OPS-002·OPS-003·OBS-001·VAL-003)을 등록했다. 소켓 연결 수 제한은 기존 접속 대체 동작이 있어 SEC-001 범위에서 뺐다. 자동 배포 방식, 호스팅, 모니터링 서비스, 클라이언트 오류 수집 여부, 빈도 제한 값은 확정하지 않고 각 작업의 수용 기준에 남겼다.
- PROGRESS: 현재 상태와 남은 일에 DEC-094·DOC-016을 연결했다.
